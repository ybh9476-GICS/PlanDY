# 랙타입 드롭다운 운용 (2026-09-18)

## 사용 규칙

- 새 랙은 현재 기준정보 목록의 첫 번째 타입을 사용한다. 초기 사본의 첫 항목은 PALLET-4L이며 [기준정보 새로 불러오기] 후에는 실제 시트에서 읽은 순서를 따른다. 목록이 비어 있으면 새 랙 생성을 안내와 함께 중지한다.
- 기준정보 타입을 수정 없이 사용하는 랙은 현재 도면에 저장된 타입 목록에 표시하지 않는다. 도면의 랙에서 실제 사용 중인 기준정보 항목 앞에 ●를 표시한다. 생성 위치를 고르는 중인 미배치 랙은 사용 아이콘에 포함하지 않는다.
- 한 베이 가로, 한 랙열 전체 깊이, 단수, 깊이 방향 셀 수, 단당 높이, 배치 가로, 배치 세로, 베이 사이 간격, 랙열 사이 간격 중 값이 달라지면 대상 코드별 도면 타입으로 표시한다. 전체 높이는 `단당 높이 × 단수`로 함께 계산한다. 위치·회전·축·잠금·대상 코드 변경은 분류 조건에서 제외한다.
- 기준정보의 배치 크기·간격 값이 제공되면 이를 적용한다. 해당 값이 없는 타입은 선택 당시 배치 크기·간격을 기준으로 이후 변경을 판단한다. 새 랙의 값이 없는 경우 기존 기본 배치 가로 10m, 세로 3m를 사용하되 최소 한 베이·한 열이 들어가도록 한다.
- 도면 타입을 선택하면 타입의 여섯 규격뿐 아니라 배치 크기와 두 간격도 함께 가져온다. 대상 코드와 방향은 유지한다. 도면 경계를 벗어나는 규격은 기존 입력 검증이 차단한다.
- [기준정보 새로 불러오기]는 목록을 갱신한다. 기존 배치의 규격은 자동으로 덮어쓰지 않는다. 읽기 실패 시 마지막으로 성공한 목록을 보존한다. 갱신된 원본 규격과 달라진 기존 랙은 도면 타입으로 분류된다.
- 현재 우측 패널의 [속성 복사]는 선택 랙의 규격·베이 수·랙열 수·마진·셀 간격을 메모리에 복사한다. 다른 랙을 선택하면 [속성 붙여넣기]로 바뀌며, 대상 랙 코드·위치·방향·축·잠금은 유지한다. 이전 [속성 저장]의 Google 마스터 추가 진입점은 제거했다.

## 저장과 호환성

도면의 저장 키와 버전 2 형식은 유지한다. 새로 연결한 랙에 선택한 원본 코드와 비교할 배치 크기·간격을 담은 선택적 `rackPreset` 정보를 보존한다. 임시저장·JSON 내보내기·실행취소·새로고침에서도 분류 기준을 유지하기 위한 정보다. 기존 문서를 읽을 때 원본 데이터에 이 정보를 자동 추가하지 않는다.

기존 문서는 저장된 타입 규격을 현재 기준정보와 비교한다. 이전 버전에서 배치 크기만 수정했는지의 이력은 남아 있지 않아, 원본에 배치 크기 값이 없으면 처음 연결된 현재 크기를 기준으로 이후 변경을 판단한다. 기존 타입 정의와 미배치 정의는 삭제하지 않는다.

## 이번 수정 파일

- `js/floor-plan-editor.js`: 첫 타입 기본 적용, 수정 여부 비교, 목록 필터와 사용 아이콘, 사용자 규격 전체 재사용, 저장 전 도면 검증 및 성공 후 연결.
- `js/floor-plan-model.js`: 선택적 원본 참조 검증·보존.
- `index.html` 및 동기화한 호환 진입 페이지 12개: 모델·에디터 캐시 버전.
- `tests/floor-plan-rack-operation-browser.cjs`: Viewer/Editor 운용 흐름 검증.
- `tests/floor-plan-model.test.js`: 원본 참조 왕복·실행취소·잘못된 참조 차단·이전 문서 보존.
- `tests/floor-plan-rack-browser.cjs`: 배치 크기도 도면 타입 조건인 새 정책과 첫 타입의 깊이에 맞춘 기대값.
- 이 문서와 `docs/floor-plan-editor.md`: 운용·검증 기록.

기준정보 읽기·저장 모듈에 함께 반영된 8열/12열 마스터 호환 기능은 보존했다. 현재 12열 형식은 기존 여덟 규격 열에 배치 가로·배치 세로·베이 사이 간격·랙열 사이 간격을 포함하며, 여덟 열만 있는 시트에 전체 배치 속성을 저장하려 하면 누락시키지 않고 오류를 안내한다. 이번 목록 작업에서 실제 시트 열이나 행을 수정하지 않았다.

## 검증

- 변경 전 `npm.cmd test` 전체 통과. 독립 Edge 브라우저에서 수정하지 않은 기준정보 랙의 도면 목록 노출, 새 랙이 두 번째 타입 PALLET-4L-DBL을 기본 선택하는 동작을 재현했다.
- 변경 후 `npm.cmd test` 전체 통과. 모델 구문·호환 진입 페이지 동기화 통과.
- Viewer/Editor 각각 실제 새 랙 배치의 첫 타입 선택, 모서리 포인터 드래그에 따른 도면 타입 등록, 실행취소 복원을 확인했다.
- 10개 항목을 각각 0.10m 또는 정수 1만큼 변경하여 W01 항목 생성, 실행취소 후 기준정보로 복원을 확인했다.
- 위치·회전·대상 코드·축·잠금 변경 제외, 배치 크기·간격 수정의 임시저장/새로고침 보존, W02에 W01의 10개 규격 재사용을 확인했다.
- 생산 코드의 공개 시트 읽기 기능으로 모의 갱신 순서·실패 보존을 검증했다. 실제 공개 시트에서도 5개 타입 읽기 성공을 확인했다.
- 실제 저장 모듈에 모의 Google 인증/Sheets 응답을 제공하여 403 실패 시 기존 도면 항목 유지, 정상 추가 1회·12개 값·읽기 확인 후 선택 랙만 기준정보 전환, 임시저장/새로고침/갱신 후 연결 보존과 이후 재수정 시 도면 타입 재등록을 확인했다.
- 기존 주요 19개, 랙 12개, 개별 목록 4개, 속성 저장 5개, 정밀도 7개, Viewer 7개, 축 6개, 화면 이동/Grid 9개, 코드 중복 4개, 패널 폭 조절 5개, 헤더 갱신/전체 화면, 랙 패널 배치 검사 통과.
- 검사 중 이전 랙 검사의 실행취소 후 기준정보 복원 기대값이 실패했다. 배치 크기 수정이 남아 있는 상황은 새 정책에서 도면 타입이므로 해당 기대값을 수정하고 같은 절차로 통과했다. 함께 갱신된 마스터 열 검사와 모의 응답의 일시적 불일치도 최종 코드로 재검증하여 통과했다.

자료: `output/floor-plan-rack-operation/before.png`, `viewer.png`, `editor.png`와 관련 브라우저 검사 출력. 독립 Edge headless 프로필의 마우스·키보드 조작이다. 사용자 Chrome 프로필과 모바일 터치는 검사하지 않았다.

실제 Google 쓰기는 OAuth 웹 클라이언트 ID가 없어 수행·검증하지 않았다. 실제 저장 성공 후의 타입 전환은 모의 응답 검증이며, 실제 시트 쓰기 완료로 판정하지 않는다. 사용자 브라우저 저장 데이터와 배포 사이트는 변경하지 않았다.
