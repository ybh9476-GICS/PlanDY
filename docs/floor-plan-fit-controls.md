# 도면 맞춤 아이콘·단축키·아이콘 툴팁 (2026-09-18)

## 적용 내용

- 전체 맞춤과 선택 맞춤을 도구줄에서 도면 내부 오른쪽 아래로 이동했다. 외곽 맞춤과 중심 대상 맞춤 SVG 아이콘만 표시하며 도면을 확대·이동해도 버튼 위치는 고정된다.
- Shift+F는 전체 맞춤, F는 선택 맞춤이다. 선택 맞춤의 기존 대상 외곽 계산과 선택 대상이 없을 때 전체 도면으로 맞추는 동작은 유지한다.
- 로그인한 Viewer와 Editor 모두 사용한다. 입력창·선택 입력·편집 가능한 본문·팝업·한글 조합 중에는 단축키가 실행되지 않는다. Ctrl/Meta/Alt와 함께 누른 F도 처리하지 않아 브라우저 찾기 등을 유지한다.
- 아이콘 버튼은 브라우저 기본 툴팁으로 명칭과 단축키를 표시한다. 단축키가 없으면 명칭만 표시한다. 접근성 이름도 함께 제공한다.

| 아이콘 버튼 | 툴팁 |
|---|---|
| 새 도면 | 새 도면 |
| 실행 취소 | 실행 취소 (Ctrl+Z) |
| 다시 실행 | 다시 실행 (Ctrl+Shift+Z / Ctrl+Y) |
| 확대 / 축소 | 확대 / 축소 |
| 전체 맞춤 | 전체 맞춤 (Shift+F) |
| 선택 맞춤 | 선택 맞춤 (F) |
| 정렬 안내 설명 | 정렬 안내 설명 |
| 랙 잠금 | 랙 잠금 / 랙 잠금 해제, 현재 상태에 따라 변경 |
| 축의 다섯 지점 | 축 설정 왼쪽 위 / 오른쪽 위 / 중심 / 왼쪽 아래 / 오른쪽 아래 |

카메라(보는 위치와 배율)와 버튼 표시만 변경하며 도면 저장 데이터나 임시저장 상태는 변경하지 않는다.

## 수정 파일

- `js/floor-plan-editor.js`: 맞춤 버튼 이동·SVG 아이콘, 아이콘 명칭·툴팁·키보드 접근성 표기, F 단축키와 입력 보호.
- `css/floor-plan-editor.css`: 도면 프레임, 내부 고정 버튼, 작은 화면 높이 유지.
- `index.html` 및 동일한 호환 진입 페이지 12개: 에디터 JS·CSS 캐시 버전 및 페이지 동기화.
- `tests/floor-plan-fit-browser.cjs`: Viewer/Editor 맞춤·단축키·툴팁·입력 보호·작은 화면 검사.
- 이 문서와 `docs/floor-plan-editor.md`: 검증 기록.

## 검증 결과

- 변경 전과 변경 후 `npm.cmd test` 전체 통과. JS 구문 검사와 호환 페이지 동기화 통과.
- 변경 전 독립 Edge에서 도구줄의 글자 맞춤 버튼, Shift+F 미동작, 실행 취소 툴팁 누락을 확인했다.
- 변경 후 Viewer/Editor 각각 도면 안쪽 오른쪽 아래에 두 SVG 버튼이 있고 도구줄에서 제거된 것을 확인했다.
- 확대 후 Shift+F로 전체 맞춤, F로 현재 랙 맞춤을 실행하고 버튼 클릭 결과와 화면 좌표·배율이 일치함을 확인했다. 저장 문자열과 임시저장 버튼 상태도 유지했다.
- 실제 키보드로 코드 입력창에서 f, 도면 설정 이름 입력창에서 Shift+F를 입력해 화면 맞춤이 실행되지 않음을 확인했다. Ctrl+F도 화면을 바꾸지 않았다. 축 버튼에 포커스가 있어도 F는 선택 맞춤을 실행했다.
- 화면의 아이콘 버튼에 툴팁이 없는 항목이 없음을 확인하고 명칭·단축키 문자열, 잠금 후 안내 변경을 검사했다. 브라우저 기본 툴팁은 `title` 속성을 사용한다.
- 브라우저 폭 720px에서도 버튼이 도면 내부에 유지되고 도면 영역의 가로 넘침이 없음을 확인했다.
- 기존 주요 19개, 화면 이동/Grid 9개, 축 6개, 패널 폭 5개, 헤더/전체 화면, Viewer 7개 브라우저 검사 통과.
- 초기 자동 화면 배치 직후 좌표를 기준으로 비교한 검사에서 0.5px 차이가 발생했다. 실제 전체 맞춤 버튼을 클릭한 결과를 기준으로 단축키를 비교하도록 검사 절차를 수정하여 동일 결과를 확인했다. 최종 미해결 실패 없음.

화면 자료: `output/floor-plan-fit/viewer.png`, `editor.png`. 검증은 독립 Edge headless 프로필의 실제 클릭·키보드·포인터 조작과 화면 확인으로 수행했다. 사용자 Chrome 프로필, 모바일 터치, 실제 한글 IME 조합 상태는 검사하지 않았다. 한글 조합은 이벤트의 조합 중 상태로 차단한다. 사용자 저장 데이터·외부 시트·배포 사이트는 변경하지 않았다.


## 전체 맞춤 아이콘 모양 변경 (2026-09-18)

사용자 참고 이미지에 따라 네 모서리 안의 사각형을 2×2 격자로 변경했다. 선택 맞춤 아이콘, 버튼 위치, Shift+F, 툴팁은 유지했다. 수정 파일은 js/floor-plan-editor.js, index.html과 동기화한 호환 진입 페이지 12개(에디터 캐시 버전)이다. 변경 전후 npm.cmd test 전체 통과 및 기존 맞춤 브라우저 검사에서 Viewer·Editor의 클릭/단축키·입력 보호·툴팁·작은 화면 유지 확인. 도면 데이터와 저장 방식은 변경하지 않았다.

전체 맞춤 아이콘 변경의 첫 브라우저 검사에서는 도면 설정 버튼 탐색 시간 초과가 발생했다. 최신 검사 절차로 재실행하여 Viewer·Editor 모두 통과했으며 최종 실패는 없다.


## 확대·축소 도면 내부 이동 (2026-09-18)

확대·축소 버튼을 도구줄에서 도면 내부 오른쪽 아래로 옮겼다. 순서는 축소, 확대, 전체 맞춤, 선택 맞춤이다. 네 버튼 모두 기존 맞춤의 32×32px 크기·테두리·배경·그림자·호버 스타일과 18px SVG를 사용한다. 확대/축소 툴팁과 기존 배율 조절 계산은 유지한다. 수정 파일: js/floor-plan-editor.js, index.html 및 동기화한 호환 진입 페이지 12개(에디터 캐시), tests/floor-plan-fit-browser.cjs, 이 문서.

변경 전후 npm.cmd test 전체 통과. Viewer·Editor에서 변경 전 상단 확대·축소 버튼을 확인했고, 변경 후 네 SVG 버튼의 순서·크기·도면 내부 배치, 확대 후 배율 증가 및 축소 후 복원, 기존 F/Shift+F·입력 보호·툴팁·임시저장 상태 유지와 폭 720px에서 도면 안쪽 배치를 확인했다. 화면: output/floor-plan-fit/viewer.png, editor.png. 검증은 독립 Edge headless이며 사용자 Chrome 프로필/모바일 터치는 미검사다. 도면 저장 데이터·외부 시트·실제 배포 사이트는 변경하지 않았다.
