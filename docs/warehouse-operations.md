# 3D 물류 흐름 모의 운행

## 기준정보

`운영 경로` 시트에서 경로 코드, 입고/출고, D 도크, B 버퍼, S 스테이션, 담당 AMR, 사용 여부, 버퍼 수용 팔레트 수, 우선순위를 설정한다. 번호 자체에는 입고/출고 의미를 고정하지 않는다. 숫자가 작은 우선순위부터 배정한다.

| 경로 | 방향 | 도크 | 버퍼 | 스테이션 | AMR |
|---|---|---|---|---|---|
| IN01 | 입고 | D01 | B01 | S02 | AMR-002 |
| IN02 | 입고 | D02 | B02 | S03 | AMR-003 |
| OUT01 | 출고 | D03 | B03 | S01 | AMR-001 |

`작업지시` R열 `경로 코드`로 작업을 연결한다. 완료·취소 작업은 실행하지 않는다. 품목·수량·작업 구분·담당 AMR을 읽는다. 현재 한 작업은 한 팔레트이며, 수량을 수용할 수 있는 랙 셀이 있어야 한다. 다른 경로의 작업과 품목·수량을 임의로 바꾸지 않는다.

평면도의 B01·B02 번호는 2026-09-16 사용자 선택에 따라 교환했다. AS20:AX25는 B01, AS30:AX35는 B02이며 T 형상은 변경하지 않았다.

## 동작

- 입고: 차량 하역 → D → CV → B → AMR → S → 셔틀·리프트 → 랙 적치.
- 출고: 랙 피킹 → 셔틀·리프트 → S → AMR → B → CV → D → 차량 상차.
- AMR은 담당 T 통로에서 상차·운반·하차하고 원래 상차 지점으로 복귀한다.
- AMR·셔틀은 `설비 마스터`의 `설정 이동 속도(m/s)`를 그대로 사용한다. 컨베이어 물품은 1.5m/s로 이동한다. 화면 갱신이 느려도 경과 시간을 작은 계산 단위로 나누어 반영하며, 탭이 숨겨진 동안에는 운행을 멈춘다.
- 셔틀은 사용 가능한 설비 중 해당 리프트로 연결되는 설비를 배정한다. 필요하면 기존 리프트로 단을 이동하고 ST를 통해 새 리프트로 이동한다. 네 번째 셔틀은 기존 리프트의 최상단에서 대기한다.
- T·CV·ST 연결이 없거나 리프트/재고/빈 셀/정상 설비가 없으면 대기 사유를 표시한다. 연결이 없는 바닥을 가로질러 운반하지 않는다.
- 팔레트는 한 작업에 하나의 오브젝트만 사용한다. 소유자를 변경하며 설비마다 새 박스를 복제하지 않는다. 팔레트·박스 크기는 해당 랙 셀 기준을 유지한다.
- 같은 T 연결 구역은 한 작업씩 사용한다. 셔틀은 왕복 경로의 단별 이동 공간과 리프트를 함께 예약하고 복귀·인계 후 해제한다. 서로 겹치지 않는 경로나 다른 단은 동시에 운행하며, 겹치는 예약은 먼저 요청한 작업 순서로 배정한다. 경로를 부분적으로 점유하지 않아 마주 오는 셔틀끼리 서로 막히지 않게 한다. 스테이션·버퍼 인계가 막힌 설비의 빌보드도 실제 대기 상태를 표시한다. CV는 같은 방향의 팔레트 여러 개를 0.3m 이상의 간격으로 연속 운반한다. 각 D/B 진입부는 최소 5초 간격으로 순차 투입하고 합류·코너 주변만 예약하며, 공통 구간을 반대로 주행하는 경로는 기존 팔레트가 나갈 때까지 진입을 기다린다. 버퍼 예약은 도착 직전에 받고, 가득 차면 컨베이어 위에서 뒤따르는 팔레트도 간격을 유지하며 대기한다. 출고 버퍼는 팔레트가 컨베이어 진입부를 빠져나오면 다음 AMR이 사용할 수 있게 한다. 장애 발생 시 운반 중 물품과 예약을 유지한다.
- 현재 모의 운행은 미완료 작업지시별로 팔레트를 하나씩 추가해 기존의 2배를 운반한다(현재 입고 40·출고 20팔레트). 추가 작업·바코드에는 `-P2` 등의 접미사를 붙인다. 팔레트 한 개의 물품 수량과 크기는 유지하며, 실제 기준정보 시트에는 작업을 추가하지 않는다.
- D·B 대기 팔레트는 설비 인계점에 가까운 자리부터 0.1m 간격의 행 단위로 채운다. 바닥 자리가 모두 차면 같은 순서로 다음 층에 쌓는다. 팔레트 바닥 크기는 랙 셀의 단위 적재물 크기를 사용한다.
- B 동시 대기 수량은 `운영 경로`의 버퍼 수용 팔레트 설정과 실제 바닥에 한 층으로 배치 가능한 수량 중 작은 값을 적용한다. 기본은 버퍼당 1팔레트다.
- 입고는 접근 가능한 빈 셀을, 출고는 품목·수량이 맞고 보류/불량이 아닌 접근 가능한 셀을 선택한다. 내부 셀을 관통하는 경로는 만들지 않는다.

## 화면과 데이터

하단에 경로별 단계와 대기 사유를 표시한다. `일시정지`/`운행 재개`는 현재 화면의 시뮬레이션만 제어한다. 빌보드와 설비 목록은 모의 동작 상태를 표시하고, 통신 상태는 기준정보에서 읽은 값을 유지한다.

AMR·셔틀·스캔 터널을 선택하면 우측 패널에 `작업 이력 보기` 버튼을 표시한다. 버튼을 누르면 해당 설비의 이력 테이블을 팝업으로 표시하고, 운행 중 변경 사항을 자동 갱신한다. 팝업은 닫기·Esc·배경 클릭으로 닫으며 버튼으로 포커스를 돌려준다. AMR·셔틀은 물품 정보·바코드·작업 상태 라벨·배정 시간·상차 지점/시간·하차 지점/시간을, 스캔 터널은 통과 시간·물품 정보·바코드·인식 상태·도착지를 표시한다. 배정 시간은 경로와 설비가 결정된 시점이며, 상하차 시간은 물품 소유권이 실제로 인계된 시점이다. 아직 수행하지 않은 시간은 `—`로 표시한다. 같은 물품을 인계받는 AMR과 셔틀은 작업지시의 동일한 바코드를 사용하며, 바코드가 없으면 스캔 터널과 같은 `HU-작업코드`를 사용한다. 완료된 운반 기록은 빈 설비의 복귀 상태로 덮어쓰지 않는다. 현재 모의 운행의 이력이며 화면 재진입·시트 새로고침 시 초기화된다.

적치/피킹은 현재 화면의 슬롯 재고와 KPI에 반영한다. 실제 `재고 현황`·작업 상태·도착 시간은 자동으로 시트에 쓰지 않는다. `시트 새로고침`이나 화면 재진입 시 기준정보를 다시 읽고 모의 운행을 초기화한다. 설비 사용 여부·통신 상태 변경도 새로고침 시 반영한다. 실설비 제어 기능이 아니다.

## 검증

`npm.cmd test`에 실제 평면도 경로 fixture, 단절된 경로 차단, 인계 시 물품 소유권, 목적지 예약, 통신 장애 중 정지·복구 테스트를 포함한다. 브라우저에서는 세 작업의 인계 및 완료, Viewer/Editor, 일시정지/재개를 확인한다.
