# 랙타입코드 직접 입력 (2026-09-17)

`평면도 에디터 > 속성 저장` 팝업에 랙타입코드와 랙타입명을 함께 표시한다.

- 팝업을 열 때 `RACK-시간문자열-임의문자열` 코드가 기본으로 채워진다. 도면 내부 CUSTOM 코드는 그대로 원본에 쓰지 않는다.
- 사용자가 코드를 직접 수정할 수 있다. 저장 시 공백을 제거하고 대문자로 정리한다.
- 기존 모델과 동일하게 영문으로 시작하는 1~24자의 영문·숫자·하이픈·밑줄만 허용한다.
- 저장 직전에 실제 원본의 코드 목록을 읽고 공백/대소문자를 정리해 중복을 검사한다. 중복이면 원본 추가 요청을 실행하지 않고, 현재 팝업에서 오류를 표시하며 코드 입력칸을 선택한다.
- 중복 코드를 다른 값으로 자동 변경하거나 기존 행을 덮어쓰지 않는다. 사용자가 수정하고 다시 저장한다.
- 코드와 이름 입력칸 모두 Enter로 저장할 수 있다. 한글 조합 중 Enter는 저장을 실행하지 않는다. 실제 운영체제 IME 조합 검증은 수행하지 않았다.
- 같은 이름이면 저장 시간을 붙이는 기존 동작은 유지한다. 코드 중복 검사 실패 시 이름에 시간을 붙이지 않는다.
- 저장 오류가 발생하면 진행 중 문구를 지운다.

## 수정 파일

- `js/floor-plan-editor.js`: 두 입력칸, 기본 코드 표시, Enter 저장, 중복 시 포커스, 오류 진행 문구 정리
- `js/floor-plan-rack-master.js`: 코드 생성/형식 검사 공개 함수, 명시적 코드 저장, 원본 코드 중복 검사
- `index.html`, 동일한 호환 진입 페이지 12개: 캐시 버전 갱신 및 동기화
- `tests/floor-plan-rack-master.test.cjs`: 직접 지정/정규화/중복/형식/자동 코드 검사
- `tests/floor-plan-rack-save-browser.cjs`: 기존 숫자 속성/삭제/저장 검사에 코드 입력 검증 추가
- 이 문서 및 기존 평면도 사용/저장 문서: 변경 기록

## 검증

변경 전후 `npm.cmd test` 전체 통과. 변경 전 Edge의 저장 팝업에 코드 입력칸이 없는 동작을 재현했다.

Edge 독립 프로필 Viewer와 Editor에서 다음 조작을 검증했다. Google 계정 승인과 원본 응답만 모의했다.

1. 속성 저장 클릭: 기본 코드 표시, 가운데 팝업 확인
2. 잘못된 코드 입력/저장: 형식 오류, 팝업 유지
3. 기존 코드 ` existing ` 입력/저장: `EXISTING`으로 정리, 중복 안내, 추가 요청 0회, 기존 행과 이름 유지
4. ` my-rack-01 `로 수정/Enter: `MY-RACK-01`로 한 번 추가, 재읽기로 확인
5. 다른 코드와 중복 이름 저장: 해당 코드 유지, 이름에 한국 저장 시간 추가

기존 기본 편집 브라우저 회귀 19개 묶음도 통과했다. 최종 실패 항목 없음. 기존 독립 초안 저장 형식/키, 다른 메뉴 권한, 계산 모델은 변경하지 않았다.

화면과 결과: `output/floor-plan-rack-type-code/`. 기존 Google OAuth 설정은 비어 있으므로 실제 Google 로그인/원본 추가는 미검증이며, 테스트 행을 원본에 쓰지 않았다. 여러 사용자의 동시 저장 중복을 원자적으로 차단하는 서버 연결은 포함하지 않는다. 사용자 Chrome 프로필/모바일 터치/실제 한글 IME 조합은 검증하지 않았다.
